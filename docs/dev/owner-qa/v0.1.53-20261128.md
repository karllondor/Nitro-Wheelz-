## Open items for the Opus integration owner (not fixed by this record)

1. **System BACK leaves the game (item 2).** v0.1.52 turned `quit_on_go_back` off and added the `AndroidBack` autoload
   (`game/scripts/ui/android_back.gd`); the CI emulator (API 35) returns from DEVELOPER to the menu with a real
   `KEYCODE_BACK`, so the cause on the owner's phone is **not yet known**. Candidates to check, none verified:
   - the owner pressed system BACK a second time on the main menu — by design the main menu leaves the game on a phone
     (`boot.gd go_back`, Android convention);
   - the phone uses Android predictive back / gesture navigation and the event does not reach `NOTIFICATION_WM_GO_BACK_REQUEST`
     in the same way as on the emulator's three-button navigation;
   - the exported build ignores `application/config/quit_on_go_back=false`.
   Needs one adb capture of `logcat -s godot` while pressing BACK once on DEVELOPER (or one precise sentence from the owner:
   which screen, how many presses). Do not close #65 until this is answered.
2. **"Hold on DRIVE does nothing until release"** is the normal button behaviour (a press counts on release). If the owner
   wants a different feel, that is a new request; no defect is assumed.
